# 应用时间锁

简体中文 | [English](README.en.md)

给自己的安卓手机加一次使用前的决定：先选用多久，到时再决定是否继续。

支持 **Android 13 及以上**。目前只在小米 13（Android 16 / HyperOS 3.0）做过真机验证，其他品牌需要自行验证，不能保证所有机型都能持续后台运行。

## 安装与授权注意事项

1. 从本仓库的 [Releases](https://github.com/yerlyrogowski-stack/App-Time-Lock/releases) 下载 APK。安装时，如系统询问是否允许当前浏览器或文件管理器安装未知应用，仅为你信任的安装来源开启；安装完成后可关闭该来源权限。
2. 打开应用，选择受控软件，点击首页“开启使用提醒”，阅读用途说明并进入系统的无障碍设置，开启“应用时间锁 · 使用提醒”。这是识别前台应用、显示选时界面和到时提醒的必要授权。
3. 若系统提示“受限设置”，在系统的本应用“应用信息”页面查找允许受限设置的选项，按系统提示完成后再开启无障碍。入口会随品牌和版本变化；如果设备管理政策不允许授权，本应用无法提供保护，不要绕过设备管理限制。
4. 若手机提供“自启动 / 后台自启动”，为本应用开启；若提供省电或后台活动设置，允许后台运行并取消对本应用的省电限制。小米的具体设置见下文。其他品牌入口名称不同，以上是需要检查的设置类型，并非每部手机都有相同开关。
5. 常用一键清理时，如系统支持，可将“应用时间锁”锁定在最近任务中，减少被清理的机会。不要把它与需要划掉后重置额度的目标应用混淆。
6. 返回首页确认“提醒服务已连接”，再实际打开受控应用确认弹出时长选择界面。自启动不能代替无障碍授权；显示已连接也不等于服务永远有效。

普通用户**不需要开启 USB 调试、USB 安装或 USB 调试（安全设置）**；这些仅用于开发者连接电脑测试。应用也不要求设备管理员、使用记录访问、普通“显示在其他应用上层”或精确闹钟权限。

### 换手机后的自测

- 打开受控应用，确认先选择时长才能使用。
- 自定义 1 分钟，持续停留在目标应用，确认到时出现提醒。
- 普通切到桌面再返回，确认保留剩余时间。
- 从最近任务划掉目标应用再重开，确认重新选择时长。这项依赖系统任务信息，不能保证所有品牌都支持。
- 测试侧边栏点击展开和自动收回；关闭侧边栏后，计时及到时提醒仍应正常。
- 手机重启、系统升级、长时间待机或清理后台后，重新确认服务状态和实际拦截效果。

若没有弹出提醒，依次检查受控列表、无障碍服务、自启动和省电限制；系统关闭服务后需要重新开启。强行停止、撤销权限或卸载本应用会停止保护。这是个人时间管理工具，不是不可绕过的强制锁。

## 使用流程

1. 安装 APK，打开“应用时间锁”。
2. 在“应用”页勾选要控制的软件。
3. 返回首页，点击“开启使用提醒”，阅读用途说明后进入系统设置。
4. 开启“应用时间锁 · 使用提醒”无障碍服务，再返回本应用确认“提醒服务已连接”。小米手机还应完成下面的后台运行设置，并实际打开受控应用确认提醒出现。
5. 打开受控应用，选择 **10 / 20 / 30 分钟**或自定义 **1—180 分钟**，点击“开始使用”。
6. 倒计时侧边栏默认隐藏于屏幕边缘，仅留细小触发条，不显示时间。点击后以约 240 毫秒动画滑出显示倒计时，5 秒后自动滑回，计时持续。触发条及展开面板均可拖动至屏幕两侧。在“设置 → 倒计时侧边栏”可关闭显示，不影响计时或到时提醒。
7. 到时轻震并显示提醒。选择“结束使用”返回桌面，或“再用一会”重新选择时长。

各应用分别计时。跨午夜和重启保留已保存的余额。取消勾选会清除该应用余额。

## 后台移除与普通切换（1.1.0）

- 按 Home、普通切后台、切换其他应用、锁屏：暂停；返回同一个任务继续原来的时间。
- 从最近任务划掉目标应用后重新打开：检测到同一次开机内的新任务编号时，清空上次额度并重新选择时长。
- 应用内部普通页面跳转仍在同一任务中，不重置。计时器是否展开、是否显示也不影响余额。
- 这是任务重建检测，不是直接接收其他应用的“被划掉”通知。返回键结束整个任务后再次建立任务也会重新选时长；多任务文档应用暂不支持。
- Android 无公开的无障碍窗口任务编号 getter。兼容层只提取系统窗口描述中的任务编号，不保留描述或标题；该格式不是稳定 SDK 合约，系统未提供编号、格式变化、升级时尚无基线或手机重启时，保守保留余额。不能承诺所有系统均能识别后台移除。
- 实现依据：[AOSP AccessibilityWindowInfo](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/main/core/java/android/view/accessibility/AccessibilityWindowInfo.java)。真机结果见 TESTING.md。

## 小米 13 / HyperOS

已连接的测试设备报告 Android 16（API 36）、HyperOS 3.0。实际验证结果见 [TESTING.md](TESTING.md)。

- 如系统提示“受限设置”，进入本应用的系统应用信息页，按系统提示允许后，再开启无障碍服务。
- 在本应用的系统“应用信息”中开启“自启动 / 后台自启动”，进入“省电策略”选择“无限制”。本次小米 13 真机测试中，“智能限制后台运行”下观察到了后台停止响应；改为“无限制”后继续验证。常用一键清理时，可在最近任务中锁定本应用。不同系统版本入口可能不同。
- 自启动不能代替无障碍授权，也不保证服务永远不被系统关闭。服务连接状态只代表当前连接，实际打开受控应用出现提醒才是有效检查。
- 关闭权限、强行停止或卸载本工具后，保护停止。重新打开本工具并检查服务状态。
- 支持普通单应用全屏。分屏、画中画、厂商小窗、应用分身及工作资料空间暂不支持。
- 拦截覆盖目标应用的前台操作，不停止其进程或后台音视频；应用启动瞬间可能先显示目标画面。

## 隐私与必要权限

- 无网络权限、无账号、无广告、无云同步或使用历史。
- 仅保存受控包名、各应用当前额度和最近任务编号/开机编号、授权说明确认状态、浮窗位置、侧边栏开关。
- 无障碍服务具备系统窗口访问能力；代码仅处理窗口类型、焦点、ID、包名等元数据。事件缺少包名时，仅读取窗口根节点的包名且关闭预取；不遍历节点树，不读取文字或截图。
- 震动权限用于到时轻震。不需要设备管理员、普通悬浮窗、使用记录或精确闹钟权限。
- 系统设置、桌面、电话入口和本工具不可加入受控列表。

## 开发与构建

原生 Kotlin + Compose / Material 3。最低 Android 13；compile/target SDK 36。

固定版本：AGP 8.13.2、Gradle 8.13、Kotlin 2.2.21、Compose BOM 2025.12.01、JDK 17。

目录：

- `app`：主界面、本地 DataStore、无障碍服务、浮窗与拦截页。
- `core`：不依赖 Android 的计时状态机和窗口判断规则，以及单元测试。
- `fixture`：专用真机测试应用，不包含用户内容，也不属于正式产品。

本电脑运行：

```powershell
.\build.ps1
```

脚本默认使用 D 盘的 SDK、Gradle 缓存和已存在的 Java。可以提前设置 `JAVA_HOME` / `ANDROID_HOME` 使用自己的安装目录。脚本在 Windows 系统启用了单一 HTTP 代理时会将其传给 Gradle。

其他环境：设置 Android SDK 和 JDK 17 后执行 `./gradlew :core:test :app:assembleDebug :app:lintDebug`。

默认构建结果：`app/build/outputs/apk/debug/app-debug.apk`。交付版本使用 `personal` 构建，启用代码和资源压缩，可运行 `.\build.ps1 -Tasks ':core:test',':app:assemblePersonal',':app:lintDebug'`，结果在 `app/build/outputs/apk/personal/app-personal.apk`。这两种构建均使用本机调试签名供个人试用；发布商店前需要独立的正式签名和上架审核。后续覆盖升级必须保留相同签名，源码压缩包不含私钥。

## 恢复与误差

计时采用单调时钟。切换或到时立即保存，使用中每 5 秒写一次检查点。异常进程退出可能最多少扣约一个检查点间隔；服务中断期间不补扣时间。重新连接服务后，要先确认当前前台应用，才会继续计时。
